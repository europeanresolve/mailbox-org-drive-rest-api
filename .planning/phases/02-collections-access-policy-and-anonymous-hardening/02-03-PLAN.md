## Phase Goal

**As a** deployer running a website for a small organisation, **I want to** define collections in config, let the website submit forms to hardened anonymous create endpoints, and manage the records through API-key-protected CRUD with default-deny access, **so that** form submissions land safely in the system of record without me running a CMS.

Source: ROADMAP Phase 2 Goal and success criteria 1-5, restated in user-story form. This plan delivers the last clause of success criterion 5 (the Kong reference config in `deploy/`) and applies D-07 to the planning documents.

<objective>
User story slice: a deployer who puts Kong in front of the API can start from a reference config that rate-limits and keeps personal data out of gateway logs, and the docs no longer promise in-API CAPTCHA.

Purpose: SEC-09, and SEC-07 closed as dropped per D-07 (CAPTCHA stays with the caller; the first adopter's backend verifies it before an apiKey create, D-06).
Output: `deploy/kong.yml`, `deploy/kong-check.sh`, README sections, REQUIREMENTS.md and ROADMAP.md edits.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> Kong | untrusted requests; Kong sees full URLs, headers and bodies |
| Kong -> API | X-Forwarded-For set by Kong, believed only when Kong's address is in server.trustProxy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12 | Information Disclosure | Kong access and plugin logs | high | mitigate | Nginx access log off; file-log reduced to method, route name and status; behavioural canary check over path, query, header, body and client IP. |
| T-02-13 | Denial of Service | anonymous POST floods | medium | mitigate | Kong per-IP limit on collections-write plus request-size-limiting; the in-app limit (plan 02-05) still holds without Kong. |
| T-02-14 | Spoofing | X-Forwarded-For trust | medium | mitigate | README instructs listing only Kong's address in server.trustProxy; plan 02-05 tests that an untrusted peer's forged header is ignored. |
| T-02-15 | Repudiation | dropped CAPTCHA | low | accept | D-07: CAPTCHA is the caller's job; documented in README and REQUIREMENTS. |
| T-02-SC | Tampering | Kong Docker image | medium | mitigate | Exact tag pinned and checked to exist; reference only, never shipped in the service image. |
