## Phase Goal

**As a** deployer running a website for a small organisation, **I want to** define collections in config, let the website submit forms to hardened anonymous create endpoints, and manage the records through API-key-protected CRUD with default-deny access, **so that** form submissions land safely in the system of record without me running a CMS.

Source: ROADMAP Phase 2 Goal and success criteria 1-5, restated in user-story form. This plan delivers the /docs clause of success criterion 1 and closes the phase with the example config, README and an end-to-end canary sweep.

<objective>

Purpose: FND-04, plus COLL-01 (example config) and COLL-07 (phase-wide no-echo sweep).
Output: `src/http/docs.ts`, `server.docs`, example config, README sections, docs and example tests, the canary sweep.
</objective>

This plan runs in the same wave as 02-07 (Idempotency-Key) and shares no files with it. It documents the Idempotency-Key header from config knowledge, and it leaves idempotency's 409 and 422 out of its canary sweep because 02-07 covers them in its own canary case.

Route schemas carry no `response` or `body` schema for collections (02-01 validates in the handler), and adding response schemas would switch on Fastify's fast-json-stringify serializer, which drops or reshapes fields. So the OpenAPI content for collection routes comes from a swagger `transform` that reads the URL shape fixed by D-15 (`/v1/<name>` and `/v1/<name>/:id`) plus the method, and builds the documented schema from config. Nothing about request handling changes.

Component names per collection: `<name>.input` (the configured schema), `<name>.record` (input plus id, createdAt, updatedAt), `<name>.page` (`{ items, nextCursor }`), plus shared `AnonymousCreated` and `Problem`.

@fastify/swagger-ui serves its assets from the installed package; no CDN.
