Choices made here under CONTEXT.md "Claude's Discretion":
- MongoDB collection for a nested name: `records_<name>` with the slash kept (`records_events/2026/signups`); research verified MongoDB accepts `/` in collection names, so no encoding is needed and plan 02's store code is untouched.
- `COLLECTION_NAME_PATTERN = "^[a-z][a-z0-9-]{0,31}(/[a-z][a-z0-9-]{0,31})*$"`; mount names, API key names and the reserved list keep MOUNT_NAME_PATTERN.
- Grants: the existing exact `${collection}:${operation}` check already works because a name never contains `:`; apiKeyIssues splits a grant at its last `:`.
- OpenAPI: component keys must match `^[a-zA-Z0-9._-]+$`, so `/` becomes `_` in component names and operationIds; paths keep the real slashes.
- Ambiguous property keys: dots are already rejected (collection.INVALID_PROPERTY_NAME); this plan adds collection.MIRROR_UNSAFE_PROPERTY_NAME for the sheet-name and formula-quote characters, at every schema depth, because array field paths become sheet names (D-23).
- The worker's folder creation from plan 03-01 (`mirrorFolders` + stat + mkdir) is exercised here for the first time; any fix it needs goes into src/mirror/path.ts (a helper the worker calls), not into worker.ts, which plan 03-04 owns in this wave.

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-15 | Tampering | Drive path from nested names | high | mitigate | Every segment must match `[a-z][a-z0-9-]{0,31}`, so `..`, empty segments, encoded separators and uppercase cannot occur; names come only from config; MountView/PathGuard still checks each segment on write. |
| T-03-16 | Elevation of Privilege | route shadowing between `events` and `events/2026/...` | medium | mitigate | Static nested prefixes win over the parametric `/:id` of a shorter collection in Fastify's router; integration test checks coexistence and that GET /v1/events/2026 never returns nested data; grants are exact strings, so `events:get` cannot read `events/2026/signups`. |
| T-03-17 | Tampering | sheet names and formula references | medium | mitigate | collection.MIRROR_UNSAFE_PROPERTY_NAME rejects `: \ / ? * [ ] ( ) '` in property names at every depth, so generated sheet names and quoted references stay valid. |
| T-03-18 | Denial of Service | very deep names (MongoDB namespace length) | low | accept | No depth limit by decision (D-19); a deployer-chosen name over MongoDB's namespace limit fails on first write with a logged error type; deployer-controlled, not attacker-controlled. |
