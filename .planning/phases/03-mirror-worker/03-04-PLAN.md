Choices made here under CONTEXT.md "Claude's Discretion" (lease TTL, heartbeat, fencing, two-instance test design):
- Lease document in MongoDB collection `mirror_leases`: `{ _id: <collection name>, owner, token, expiresAt }`. TTL is `timings.leaseTtlMs` (default 60000, from plan 03-01's timings); heartbeat every TTL/3 while a pass runs; release sets expiresAt to the epoch so the next pass (on any instance) can start at once.
- Fencing: right after acquiring, the pass runs `$max: { fence: token }` on its mirror_state document; every commit filters on `{ _id, fence: token }`. A newer holder has raised the fence, so a zombie's commit matches nothing. A zombie can still finish one stale upload; the next pass corrects it through the ETag rule (D-03). This is the honest limit stated in research Pattern 2.
- Pass order: acquire → fence → read dirtySeq as seq → read records → build workbook → stat the file → decide skip or upload → heartbeat check → write → fenced commit → release.
- Skip rule (D-04): skip only when the hash matches AND the file exists AND its ETag equals lastWrittenEtag. A skip still commits mirroredSeq = seq and lastMirroredAt (the mirror is confirmed current) and logs "mirror unchanged" at info.
- External change (D-03): the file exists and either lastWrittenEtag is null or the ETags differ, or stat returns a null ETag. The pass uploads, then commits `externalChangeAt = now` and `$inc: { externalChanges: 1 }`, and logs `{ collection }` "mirror replaced an external change" at warn. A missing file is not an external change for status purposes; it is simply re-uploaded.
- Two-instance test: instance A is `collectionsApp({ role: "all", mirror: true, dbName, mirrorFolder, server: { logLevel: "debug" }, mirrorTimings: { pollMs: 25, debounceMs: 50, leaseTtlMs: 2000 } })`; instance B is the same with `role: "worker"`. The worker logs "mirror pass started" (debug) and "mirror written" / "mirror unchanged" (info) with `{ collection, token }`; the test reads both log captures and checks intervals and tokens. The lease race, takeover and fencing cases use MirrorLease and MirrorStateStore directly against a per-test database for determinism.

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Tampering | concurrent writers (src/mirror/lease.ts) | high | mitigate | Atomic findOneAndUpdate upsert with $inc token; E11000 treated as not acquired; two-instance test proves no overlapping passes. |
| T-03-11 | Tampering | zombie writer commit (src/mirror/state.ts) | medium | mitigate | `$max fence` on acquire and commits filtered on fence; heartbeat failure aborts before the write; residual stale upload corrected by the D-03 ETag rule on the next pass. |
| T-03-12 | Spoofing | lease owner identity | low | mitigate | Owner id includes a per-instance randomUUID, so no two instances share an identity; the id is never logged. |
| T-03-13 | Information Disclosure | external-change reporting | medium | mitigate | Logs and state record only the collection name, a timestamp and a count; no file content, ETag, path or staff identity. |
| T-03-14 | Denial of Service | OX version history growth (U-01/U-02) | medium | mitigate | Content-hash skip avoids a PUT (and a new OX version) when nothing changed. |
</threat_model>
