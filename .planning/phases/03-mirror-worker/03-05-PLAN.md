Choices made here under CONTEXT.md "Claude's Discretion":
- `markDirty` adds `$min: { pendingSince: now }` to plan 03-01's `$inc dirtySeq` and `$max dueAt`, so pendingSince is the time of the oldest unmirrored write.
- After a successful fenced commit at seq: when the document's dirtySeq still equals seq, unset pendingSince; otherwise set pendingSince to the time the pass read its records. Single-document updates only, no pipeline updates (portable subset, P1 D-22).
- `isDue(state, now, timings)`: `(dirtySeq > mirroredSeq || reconcileRequested)` and `now >= nextAttemptAt` (absent means due) and (`reconcileRequested` or `now >= dueAt` or `now - pendingSince >= maxWaitMs`).
- Reconcile: `requestReconcile(names)` upserts `$set: { reconcileRequested: true }` for each configured collection; the fenced commit sets it back to false. The worker calls it once in start() before the first tick and then every `reconcileMs`. The tick lists state only for configured names, which also ignores documents of removed collections.
- Backoff: `backoffMs(failures, timings) = min(backoffBaseMs * 2^(failures - 1), backoffMaxMs)`; defaults 30000 and 900000, added to MirrorTimings in src/mirror/timings.ts as test-overridable values (server.ts already passes `Partial<MirrorTimings>` through unchanged). The adapter's own retry (Phase 1) runs inside each attempt; this backoff is between attempts.
- lastError codes: the StorageError kind (`not-found`, `conflict`, `forbidden`, `unauthorized`, `rate-limited`, `unavailable`, `too-large`, `insufficient-storage`, `read-only-mount`, `invalid-path`), `workbook` for a buildWorkbook failure, `internal` otherwise. Never an error message.
- Failure state updates are fenced too: the holder that failed writes failures/nextAttemptAt/lastError with an update filtered on its fence token, so a zombie's failure cannot overwrite a newer holder's success.
</context>
