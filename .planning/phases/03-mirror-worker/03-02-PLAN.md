Choices made here under CONTEXT.md "Claude's Discretion":
- Formula guard style: an explicit string cell, text unchanged, no leading apostrophe, so a phone number `+49…` reads as typed. exceljs only produces a formula from an object value, and plan 03-01's rule is that user data reaches cell.value only as a JS primitive. The README note about CSV export comes in plan 03-07.
- Kinds: `string`, `number` (number and integer), `boolean`, `date` (string with format date), `date-time` (string with format date-time, and createdAt/updatedAt), `json` (fallback). A type list with "null" uses the non-null member when there is exactly one.
- Date cells get numFmt `yyyy-mm-dd hh:mm:ss` (date-time) or `yyyy-mm-dd` (date); exceljs converts a JS Date to an Excel serial in UTC. A value that fails to parse as a date stays a sanitised string cell.
- The header row is frozen (view ySplit 1) so staff keep the column names in view. Column widths are not set.
- `MIRROR_FORMAT_VERSION` (an integer constant, starting at 1) is part of the hashed model, so a layout change in code re-uploads every mirror once even when the data did not change.
- Array properties: planColumns records them in `arrays` (path, item schema, main-column position) and emits no main-sheet column in this plan; plan 03-03 renders their sheets and summary columns in that position.
- Property names are already free of `.` (collection.INVALID_PROPERTY_NAME), so a dotted header can never collide with a real property; plan 03-06 adds the startup rule for characters that are unsafe in sheet names.
</context>
