## Phase Goal

**As a** staff member of a small organisation, **I want to** open an always-current `.xlsx` per collection in our Drive, **so that** I can work with form submissions in the tool I already use without anyone calling the API.

Source: ROADMAP Phase 3 Goal ("Staff open an always-current `.xlsx` per collection in their Drive, written safely by a single background writer, without anyone calling the API") restated as a user story; success criteria 1-5 as reworded by D-02 and D-08 in this plan.

This plan is the tracer for the phase. One flat collection, an API write, a dirty mark in MongoDB, the background worker, a minimal workbook and a direct PUT run through the real composition root (`start()`) against the Compose stack. Every later plan expands from this slice: the full workbook (03-02, 03-03), the lease and content skip (03-04), debounce and reconciliation (03-05), nested names (03-06) and the operator API (03-07).

Design choices for this phase, made under CONTEXT.md "Claude's Discretion" and used by every later plan:
- Config layout (D-05, D-15, D-16, D-14; confirmed in Task 1): top-level `mirror: { mount, debounceSeconds, maxWaitSeconds, reconcileMinutes, maxCellLength }`. `mount` is required; the rest are optional with defaults 15, 180, 15 and 32767. Seconds follow the existing `rateLimit.windowSeconds` convention; minutes for reconcile match D-16's wording. The block is required whenever at least one collection is defined.
- `ROLE` is an env var only (D-17, P1 D-17), parsed in the loader's env stage next to PORT and LOG_LEVEL and exposed as `config.role`. It is not a config.yaml key.
- Test-only timing overrides: `start({ mirrorTimings })`, the same pattern as `adapterTimings`. `src/mirror/timings.ts` resolves `MirrorTimings = { pollMs, debounceMs, maxWaitMs, reconcileMs, leaseTtlMs }` once from `config.mirror` plus overrides. Defaults: pollMs 1000, leaseTtlMs 60000, the rest from config. Later plans consume fields; they never change server.ts to add timings.
- MongoDB collection `mirror_state`, one document per collection, `_id` = collection name. Fields used from this plan: `dirtySeq`, `mirroredSeq`, `dueAt`, `lastMirroredAt`, `contentHash`, `lastWrittenEtag`. Plans 03-04, 03-05 and 03-07 add `fence`, `pendingSince`, `reconcileRequested`, `forceUpload`, `failures`, `nextAttemptAt`, `lastError`, `externalChangeAt` to the same document.
- The dirty mark is awaited in the handler after the MongoDB write but its failure is caught and logged, never surfaced: the response does not depend on it, and tests see the mark as soon as the response arrives.
- A pass reads `dirtySeq` before it reads the records, and commits `mirroredSeq` to the value it read, so a write that lands during the pass leaves the collection dirty.
- Records are read whole per pass with `RecordStore.allSorted(name)` in `(createdAt, _id)` order (D-12). Collections hold tens of writes a week, so streaming is not needed.
- The main sheet is named after the last segment of the collection name, cut to 31 characters (D-24), already in this plan, so a slash can never reach exceljs as a sheet name.
- Test helpers: `test/helpers/mirror.ts` is written complete in this plan (fetch, etag, list, raw put, delete, parse, waitUntil) so that later plans in the same wave never edit it. `collectionsApp` gains `role` (default `api`, so existing tests start no worker), `mirrorTimings`, `mirror: true` (a per-app mirror folder under the run folder, created with MKCOL before start), and `dbName` / `mirrorFolder` overrides that let plan 03-04 start two instances on one database and one folder.

Commit convention: `test(03-01): ...` (RED) before `feat(03-01): ...` (GREEN) (Phase 1 D-01); every message ends with a blank line, `Refs: #2`, then the session's Co-Authored-By line.
