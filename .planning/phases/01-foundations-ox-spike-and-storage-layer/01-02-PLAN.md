## Phase Goal

**As a** developer building on this service, **I want to** start the local stack with one command, run the full test suite green in CI, and rely on a configurable, path-safe, retry-aware storage layer, **so that** I can build the website-forms features on documented mailbox.org WebDAV behaviour without touching a real Drive or leaking secrets and personal data into logs.

Source: ROADMAP Phase 1 Goal and success criteria 1-5.

This plan delivers the "documented mailbox.org behaviour" part as raw material. It produces a reviewed, anonymised spike run that plan 01-10 turns into the compatibility matrix and fixtures, and plan 01-12 into adapter adjustments.

<objective>
User story: as a developer building on this service, I want a one-command local stack, a green CI suite and a safe storage layer, so that I can build the forms features on documented mailbox.org behaviour without leaking data.

This plan's slice: build a one-off, dependency-free probe script and a UI checklist, prove the script on a local throwaway WebDAV server, then have the user run it once against their mailbox.org account.

Purpose: STOR-01 needs *observed* OX behaviour (ETag, If-Match, LOCK, MOVE-over-existing, versions/trash, `Last, First` encoding). The spike runs in Wave 2, right after the toolchain plan that installs `webdav` (needed by P-19), so its results reach the matrix (01-10), the adapter adjustments (01-12) and the Phase 3/4 designs.
Output: `tmp/spike/ox-probe.mjs` and `tmp/spike/dry-run.sh` (gitignored, never committed, per D-07), and a user-reviewed `anon/` output folder outside the checkout.
</objective>
