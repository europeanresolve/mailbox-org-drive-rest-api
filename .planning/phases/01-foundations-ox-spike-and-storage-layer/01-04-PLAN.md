## Phase Goal

**As a** developer building on this service, **I want to** start the local stack with one command, run the full test suite green in CI, and rely on a configurable, path-safe, retry-aware storage layer, **so that** I can build the website-forms features on documented mailbox.org WebDAV behaviour without touching a real Drive or leaking secrets and personal data into logs.

Source: ROADMAP Phase 1 Goal and success criteria 1-5.

This plan delivers the logging half of ROADMAP success criterion 2. An operator gets structured logs with route templates and no bodies or personal data, proven by a canary test. Later plans extend the harness to config errors (01-06), the storage adapter (01-08) and readiness (01-09).

<objective>
User story: as a developer building on this service, I want a one-command local stack, a green CI suite and a safe storage layer, so that I can build the forms features on documented mailbox.org behaviour without leaking data.

This plan's slice: replace Fastify's default request logging with an allow-list harness: one line per request, error lines without messages, problem+json error responses, and a canary test across every HTTP error path.

Purpose: FND-03. Collection records in Phase 2 are personal data, and default Fastify logging leaks URLs and error messages (research: 6 leaks in 20 lines).
Output: `src/http/logging.ts`, `buildApp` logger options, the `captureLogs` test helper and the canary test.
</objective>
