## Phase Goal

**As a** developer building on this service, **I want to** start the local stack with one command, run the full test suite green in CI, and rely on a configurable, path-safe, retry-aware storage layer, **so that** I can build the website-forms features on documented mailbox.org WebDAV behaviour without touching a real Drive or leaking secrets and personal data into logs.

Source: ROADMAP Phase 1 Goal and success criteria 1-5.

This plan delivers the storage port and the first half of ROADMAP success criterion 5 (the in-memory adapter passes the shared contract suite), plus the "write to a read mount is rejected" half of criterion 4.

<objective>
User story: as a developer building on this service, I want a one-command local stack, a green CI suite and a safe storage layer, so that I can build the forms features on documented mailbox.org behaviour without leaking data.

This plan's slice: define the `StorageAdapter` interface, implement `MemoryAdapter`, write the shared contract suite that WebDAV must also pass (plan 01-08), and add `MountView` so read mounts cannot be written to.

Purpose: STOR-04 and STOR-02. The contract encodes semantic outcomes (StorageError kinds), so the WebDAV adapter, the in-memory adapter and any later backend are interchangeable (research Pitfalls 4 and 7).
Output: `src/storage/{adapter,memory-adapter,mount-view}.ts`, the contract suite and tests.
</objective>

  <files>test/contract/storage-adapter.contract.ts, src/storage/memory-adapter.ts</files>

  <behavior>
    - stat: file gives kind file plus size; folder gives kind dir; missing gives not-found.
    - list:
      - an empty folder gives [];
      - entries "b", "a", "B" come back as "B", "a", "b" (code-unit order);
      - the folder's own entry is excluded;
      - a missing folder gives not-found.
    - read:
      - missing gives not-found; a folder gives conflict;
      - maxBytes 4 on a 9-byte file gives too-large;
      - a zero-byte file returns an empty Buffer.
    - write:
      - an empty Buffer creates size 0;
      - into a missing parent gives conflict; over a folder gives conflict;
      - identical bytes twice: both resolve and the read equals them;
      - two concurrent writes of different bodies to one path: a later read equals exactly one of them.
    - mkdir: new gives stat dir; existing gives conflict; missing parent gives conflict.
    - move:
      - a rename leaves the source not-found and the destination with the bytes;
      - a missing source gives not-found;
      - onto an existing file with overwrite false gives conflict, with both files unchanged;
      - with overwrite true the destination is replaced;
      - move(p, p) gives conflict.
    - delete:
      - a file then stat gives not-found; a second delete gives not-found;
      - an empty or non-empty folder gives conflict, with its children intact.
    - Adjacency: write /a, then stat /ab gives not-found.
  </behavior>
  <action>
