## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request code -> CI runner | untrusted contributions run in CI |
| CI -> GHCR | the workflow token can publish images that deployers pull |
| Renovate -> repository | an automated bot proposes dependency changes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-13 | Elevation of Privilege | workflow token | high | mitigate | Top-level permissions contents read. packages write only on the image job. |
| T-01-14 | Tampering | image publish from PR code | high | mitigate | The login step condition and the build-push `push` input are both `github.event_name == 'push' && github.ref == 'refs/heads/main'`, checked by the Task 1 workflow script. PR runs build without credentials. |
| T-01-15 | Tampering | Renovate updates | medium | mitigate | config:best-practices (minimum release age, digest pinning, lockfile maintenance). Every update arrives as a PR that must pass this pipeline. |
| T-01-SC | Tampering | dependency install in CI | high | mitigate | `pnpm install --frozen-lockfile` against the committed lockfile. pnpm/action-setup pins pnpm from packageManager. No new packages in this plan. |
</threat_model>
